# Silent Orbit v0.11.0-beta.9 — Windows generate access repair

`v0.11.0-beta.9` is a GitHub Pre-release candidate generated from the Private
source of truth through the deterministic Public Export.

## Why this candidate exists

An external `v0.11.0-beta.8` run passed the Release checksum and handoff
contract, then stopped at `generate` with a Windows `EIO: Access denied`
failure. The failed run left `dist` absent and the expected first diff at one
added Skill. This is a P1 core-flow defect, not an accepted v1 result.

The failure signature was reproduced against the immutable beta.8 tarball by
injecting the same Windows-style denial at the staged-directory publication
boundary.

## Fix

- Retry transient `EACCES`, `EBUSY`, `EIO`, `ENOTEMPTY`, and `EPERM` failures
  while staging and publishing generated files.
- Fall back to a validated copy when Windows repeatedly denies the final
  directory rename and no previous `dist` exists.
- Leave an already-current `dist` untouched on repeated generation, avoiding
  an unnecessary rename while a preview or file viewer may hold it open.
- Preserve the previous generated output on replacement failure.
- Return an actionable, path-free error if both rename and validated copy are
  denied; never expose the tester's project directory.
- Cover transient staging denial, transient and repeated rename denial,
  copy fallback, persistent-denial cleanup, and unchanged-output behavior with
  deterministic regressions.

## Compatibility and release boundary

- Package / repository: `0.11.0-beta.9`.
- CLI interface: `0.4.0`.
- Schema family: unchanged v1 contracts and hashes.
- Distribution: immutable GitHub Pre-release assets; npm remains unpublished.
- Production authority remains Public GitHub `main` after the required
  `release-gate`, consumed by the connected Netlify site.

Independent-human acceptance remains required. This candidate does not create
a v1 release or convert internal, fixture, CI, or maintainer evidence into
external acceptance.
